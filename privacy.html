Privacy Policy — Life Engine

Last updated: 10 September 2026

Life Engine is a personal automation run by one individual, Stewart Morpurgo, for his own use only. It is not a product, it is not offered to other people, and it has no users other than its operator. It reads his own Google account to assemble a short daily briefing and sends it to him on Telegram.

In one sentence: this application reads the operator's own calendar and a narrow slice of his own mailbox, uses them to write him a daily message, and shares that data with no one.

What Google data it accesses

Life Engine requests two Google scopes, both read-only. It never creates, edits or deletes anything in the Google account.

  • calendar.readonly — reads events on the operator's work, personal and holiday-rental calendars for the current day, to list what is happening and to detect when a rental guest is due to arrive or leave.
  • gmail.readonly — searches only for booking correspondence from the holiday-letting agency (messages from homeaway.com senders), to recover a guest's name and, where present, a contact number, so a reminder can say who is arriving and where. No other mail is read, and no mail is read for any other purpose.

How the data is used

Event titles, times, and the guest details described above are assembled into a short briefing and sent to the operator's own Telegram account. That is the only use. The data is not analysed for any other purpose, not used to build a profile, and not used for advertising.

Where it is stored

Calendar and mail contents are read at the moment a briefing is assembled and are not retained wholesale. What is stored is limited to:

  • the text of briefings that were sent, so the same thing is not sent twice;
  • rental booking records — guest name, property, arrival and departure dates, and a contact number when one was found — so reminders are not repeated or missed.

This is held in a private Supabase (PostgreSQL) database hosted in the United Kingdom, accessible only to the operator.

Who else sees it

Nothing is sold, and nothing is shared with any third party for their own purposes. Data passes through exactly three service providers, each acting only to deliver this application's function:

  • Supabase — hosts the database and the code that runs.
  • Anthropic — the briefing text is drafted by the Claude API from the assembled summary. Under Anthropic's commercial terms this content is not used to train models.
  • Telegram — delivers the finished message to the operator.

Limited Use disclosure

Life Engine's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Specifically: Google user data is used only to provide the briefing described above, is not transferred to others except as needed to provide that function, is not used for advertising, and is not read by humans other than the operator whose account it is.

Retention and deletion

Briefing and booking records are kept only while they remain useful and can be deleted by the operator at any time. Access can be withdrawn at any moment from Google Account permissions, which immediately and permanently ends this application's ability to read anything; any stored records can be deleted at the same time on request.

Security

Credentials are held as encrypted secrets in the hosting platform and are never stored in the source code or in the public repository. All connections to Google, Supabase, Anthropic and Telegram use HTTPS.
